# D2 + ELK 业务分区布局研究

日期：2026-09-18。状态：**自动业务识别、业务配置、区内社区和共享枢纽布局已实施。** 当前用法见 [README](../../README.md) 和 [开发指南](../../dev_guide.md#business-layout)，当前验收见 [实施验证](../validation/d2-business-layout.md)。本文保留 D2 0.7.1 的引擎边界和实施前原型数据。

## 决策

采用 **表名与外键自动推断业务分区 → 可选人工覆盖 → 区内关系布局 → 跨区枢纽调整 → 独立区域二维装箱 → D2/ELK 渲染**。

日常命令仍只需要 SQL 目录和输出路径。默认结合表名规律与真实外键推断分区，自动生成标题和配色；YAML 仅用于修正归属、标题或颜色。具体坐标和绕线交给 ELK。以下原型比较与当前自动识别的正式回归结果分开记录。

原型已经验证：淡色分区、标题、同色表头、跨区字段连线可以同时实现。共享主表的布局需要单独处理，仅增加彩色边框不能解决长线。全自动布局仍不能保证复刻人工排版的每个位置，也不能保证任意关系图没有交叉。

## 默认自动识别

现有 Schema 包含表名和外键；`d2_business.py` 负责名称家族和显式覆盖，`d2_grouping.py` 负责关系社区和枢纽层次。识别是展示层的纯函数，不执行 SQL，不调用大模型，不依赖网络服务。

1. **提取候选名称**：在数据库命名空间内，按表名的词边界寻找重复前缀及层级，识别 `books` / `books_*`、`loans_*`、`members_*` 等表族。前缀从输入中发现，不硬编码这几个业务词，也不机械地只取第一个下划线之前的内容。
2. **结合关系选分区粒度**：用组内联系、跨组引用和候选组大小筛选名称家族。没有根表、又包含多个有效子家族的宽泛前缀采用更具体的分区，例如 Library books 和 Library events。判断只依赖该前缀子树，避免添加无关表后把已有细分区合并。
3. **没有外键也可分区**：清晰重复的命名规律可以作为布局依据；无名称规律时沿用独立组件装箱，不创造关系。表名和外键给出冲突信号时，保留中性的关系布局。
4. **自动标题与颜色**：高可信表族使用前缀生成标题，如 Books、Loans、Members，并附上数据库命名空间；无法命名的社区保留中性样式，不编造业务解释。组标识来自稳定名称，自动浅色由其摘要确定，避免按本次枚举序号分配。
5. **允许少量覆盖**：显式配置优先，未覆盖的表继续自动推断。不要求用户先给所有表写一份 YAML。`t001`、`t002` 这类名称没有业务语义时，只能利用关系分组，无法可靠还原其真实业务名称。

这属于从 SQL 结构中推断业务意图；SQL 通常没有显式业务分区声明。首版不依赖表注释或迁移目录位置：当前 Table 模型没有业务描述字段，单个迁移文件也可能修改多个业务域。当前前缀、冲突和稳定性规则由独立单元测试与真实 SVG 测试验证，不依赖原型中手工指定的四个域作为正确性证据。

## 引擎边界：按实际使用的 0.7.1 验证

| 方案 | 结果与取舍 |
| --- | --- |
| 普通 D2 容器表示业务分区 | 可行。标题、背景、边框和表头使用原生 D2 样式；跨容器外键仍连到字段。 |
| 把互有关联的业务区塞进固定网格 | 拒绝。实测跨区外键偏离字段端口；官方也说明 ELK 的跨网格单元连线没有路径搜索。 |
| 网格只装没有跨格外键的独立区域 | 可行。每格包一层普通容器，表格本身保留自然尺寸；格内仍由 ELK 排线。 |
| 直接指定每张表的坐标、`near: other_table` | 不作为 ELK 能力提供；当前官方文档将这些能力限定在 TALA。 |
| 给每个业务区指定不同方向 | 0.7.1 的 ELK 适配器读取根图方向；原型中修改嵌套容器方向未产生预期布局。不能据此设计接口。 |
| 从 ELK 官网照搬大量优化参数 | 不采用。0.7.1 D2 适配器只开放算法、层间节点间距、内边距、层间边与节点间距、自环间距五项。 |
| 手工固定所有表高来压缩画布 | 原型可缩小部分枢纽，但收益有限，且会耦合字体、字段数与字号。首版保留 D2 自然尺寸。 |
| 渲染后改 SVG 坐标、删线或合并外键 | 不采用。布局应能从 D2 重新生成，真实关系与字段对应必须保留。 |

依据：[D2 网格与跨格连线](https://d2lang.com/tour/grid-diagrams/)、[位置能力](https://d2lang.com/tour/positions/)、[容器语法](https://d2lang.com/tour/containers/)、[D2 0.7.1 ELK 适配器源码](https://github.com/d2lang/d2/blob/v0.7.1/d2layouts/d2elklayout/layout.go)。适配器启用 `INCLUDE_CHILDREN` 层级布局，并为 SQL 字段建立固定位置端口；这些能力适合保留跨业务区的真实字段连接。

## 实测结果

使用本地 D2 0.7.1 实际生成 SVG，再读取 XML 检查表格区域和箭头。40 表基础用例来自 [related_tables.sql](../../tests/fixtures/related_tables.sql)：四个关系密集域，每域 10 表，域内星形加链式关系，域之间另有外键；交错表名用于避免把名称排序误当作关系聚类。

下表的“连线数”按字段对计数；复合外键每对字段一条线。“总线长/最长线”是 SVG 路径点及控制点之间的曼哈顿距离估计，不是贝塞尔曲线的精确弧长。长宽比取较长边 / 较短边。所有表格保持相同字号和字段展示设置。

| 用例 | 画布尺寸 | 长宽比 | 连线数 | 总线长 / 最长线 | 字段端点 |
| --- | --- | --- | --- | --- | --- |
| 40 表，不分组 | 4131 × 4237 | 1.03 | 71 | 70627 / 2592 | 通过 |
| 40 表，现有自动分组 | 2671 × 3553 | 1.33 | 71 | 51869 / 1851.5 | 通过 |
| 40 表，增加命名分区与配色 | 2672 × 3604 | 1.35 | 71 | 51844 / 1826.5 | 通过 |
| 41 表，所有表都引用共享主表，普通分组 | 2920 × 5341 | 1.83 | 111 | 191011 / 7053.5 | 通过 |
| 同上，自动调整共享主表的布局层次 | 2920 × 4080 | 1.40 | 111 | 123660 / 4052.5 | 通过 |
| 41 表，各域只通过共享主表相连，普通分组 | 1546 × 7978 | 5.16 | 108 | 156178.5 / 5581 | 通过 |
| 同上，自动调整共享主表的布局层次 | 2770 × 4159 | 1.50 | 108 | 108179 / 3205 | 通过 |
| 24 张无外键表，四个业务区，表高不同 | 1806 × 1348 | 1.34 | 0 | — | 无外键；无重叠 |
| 24 表，一个业务区包含多个独立关系组件 | 1580 × 2656 | 1.68 | 11 | 2781 / 1074.8 | 通过 |
| 12 表，跨区复合外键、环、中文和特殊名称、自引用 | 3769 × 1446 | 2.61 | 25 | 22360 / 3304.5 | 普通外键通过；自环见下文 |
| 负例：40 表业务区强制跨格连接 | 5682 × 1672 | 3.40 | 71 | 100046.9 / 3131 | **失败，不采用** |

结论：

- 在现有自动分组基础上，命名分区只增加约 1.5% 画布面积，71 条字段连接保留正确。主要价值是业务区域可识别，不应把现有自动分组的收益算作配色收益。
- 111 条连线的共享主表用例，自动调整后面积下降约 24%，总线长下降约 35%，最长线下降约 43%。
- 108 条连线用例的长宽比从 5.16 降到 1.50，说明单纯依赖当前分组仍可能出现长条，枢纽布局确有必要。
- 12 表复杂用例仍偏宽：布局质量需要结合结构判断，不能用“任何图都接近正方形”作为承诺。
- 所有正例均无表格重叠、无表或连线丢失。字段端点检查同时核对实际 SVG 箭头方向；自引用保留已有显式字段标签，沿用 D2 0.7.1 自环连接表边界的已知限制。

研究阶段共渲染 18 个候选图，包括方向、固定表高和手工枢纽层次等对照。上表采用原型自动枢纽策略的数据。原型使用的临时脚本引用拆分前的内部接口，不属于运行时功能或稳定重放入口。当前实现的回归入口为 `tests/integration/test_business_layout.py`。所有数据来自合成用例；这里不保存真实数据库名称、迁移内容或本机路径。

## 最小配置契约

自动识别不增加必填参数。需要覆盖自动结果时，新增一个可选参数，输入输出位置不变：

```bash
python -m erd_generator ./db/migration ./generated/schema.svg --layout-config ./erd-layout.yaml
```

```yaml
groups:
  books:
    label: Books
    tables: ["demo_library.books"]
    color: blue
  loans:
    label: Loans
    tables: ["demo_library.loans", "demo_library.loan_*"]
    color: gold
  members:
    label: Members
    tables: ["demo_library.members", "demo_library.membership_types"]
    color: green
```

仅 `tables` 必填；`label` 默认组名，`color` 默认按稳定组标识生成浅色，也可指定内置命名颜色。标题和表名仍表达归属，颜色只作辅助。业务配置与 `--fk-config` 分离：前者决定如何展示，后者声明关系，不能为了放近两张表虚构外键。

约定：

1. 只显式加载指定文件，不搜索工作目录、父目录或用户主目录中的隐式配置，确保 CI 输入明确。
2. 表选择器先精确匹配 Schema 中的完整名称，再按区分大小写的通配模式匹配；不使用正则，不猜测缺失 schema，不做跨 schema 同名回退。
3. 每张表最多属于一个显式业务区。不同区重叠匹配、零匹配规则、未知字段、重复 YAML 键、非法配色或空列表均报错；不采用“第一个规则获胜”。
4. 未匹配表继续按名称与拓扑自动安排，不能丢弃，也不能全部塞进一个巨大 Other 区。显式归属优先，自动识别和枢纽优化不得擅自把表移出已配置的业务区。
5. 同一业务区可以覆盖多个原始外键连通分量，即使这些表之间没有外键。布局合并只存在于展示计划，不修改 Schema 或关系集合。
6. `--grouping none` 关闭自动业务/社区推断与枢纽优化，显式业务区仍生效；删除 `--layout-config` 恢复无业务配置的自动布局。
7. `.d2` 源码输出支持相同配置，不依赖 D2 进程；正式实现不得靠反复渲染才能决定业务归属。

## 布局步骤与不变量

1. **解析与检查**：复用现有 SQL、附加 FK 和关系验证；解析布局配置并解析为不可变分组数据。任何错误发生在输出替换之前。
2. **决定归属**：先解析显式覆盖，对剩余表联合命名规律与真实关系推断业务分区。首版限制层级深度，避免多层大框造成额外空白。
3. **决定独立区域**：按真实外键连接，以及“同一已选定业务组”的归属关系计算展示区域。使用单独的布局邻接/并查集，不把归属边包装成 `ForeignKey`。
4. **区域内部**：有关联的业务区使用普通 D2 容器；区内复用现有关系分组与层次压缩。完全独立的子区域可以打包；所有跨格外键必须为零。
5. **共享枢纽**：对独立成组、连接至少三个其他组的单表枢纽，把邻接组安排在两侧。先暂时移除枢纽，对其余组做确定性图着色，再在中间插入枢纽层次；按预计尺寸平衡无边邻居或层次。相连的多个枢纽在中央带使用不同层次；尺寸不均和多枢纽情况已纳入回归。
6. **源文本顺序与箭头**：布局层次仅用于选择 `child -> parent` 或 `parent <- child` 的源文本写法，不是 ELK 的固定坐标/rank 约束。两种写法的真实箭头方向一致。ELK 最终决定位置；不承诺共享表一定在画布几何中心。
7. **展示与发布**：组标题、浅色背景、边框和表头写入 D2；SQL 表维持方角，连线可圆角。继续由当前 renderer 校验 SVG 后原子替换。

硬约束优先于面积：每张表恰好出现一次，字段顺序、PK/FK/UNQ、索引说明、外键数量与箭头含义不变。增删表可引起 ELK 重排；承诺相同输入的确定性，不承诺像素位置永久固定。第一版不引入多次渲染择优或自建路由器。

## 最小设计快照

```text
CLI
 ├─ SQL/FK 加载 → Schema + 已验证关系
 └─ layout_config.py → 不可变布局配置
                  ↓
     d2_business.py / d2_grouping.py / d2_layout.py → 展示分组与装箱计划
                  ↓
           d2.py + d2_emit.py → D2 源码
                  ↓
         现有 d2_renderer.py → 校验并发布 SVG
```

| 模块 | 变化与理由 | 主要依赖/风险 |
| --- | --- | --- |
| 新 `layout_config.py` | 严格 YAML 加载、选择器解析、配置数据类；复用已安装 PyYAML | 只依赖 Schema/标准库；重复键与通配冲突需要独立失败测试 |
| 新 `d2_business.py` | 命名前缀候选、与关系社区的协调、自动标题和稳定组标识 | 纯函数，调用关系分组而不反向依赖；识别不确定时保留中性关系分组，不修改 SQL 元数据 |
| `d2_grouping.py` | 自动社区与共享枢纽的层次策略 | 纯计算；确保输入顺序不影响结果，不向上依赖 CLI/renderer |
| `d2_layout.py` | 基于业务归属合并展示区域，复用尺寸估计与独立区域装箱 | 旧 `_component_size` 假定真实 FK 连通，不能直接喂给它“同组但无边”的集合；先抽取可复用的矩形装箱函数 |
| 新 `d2_emit.py`、现有 `d2.py` | 先无行为变更地移动表/字段/连线发射代码，再让 `d2.py` 编排层次 | 表结构序列化与区域编排已分开。全局 FK 信息传入表发射，跨区和跨祖先层次的 FK 标记、tooltip、字段路径均保留 |
| `d2_styles.py` | 集中定义少量区块调色板及标题样式 | 不把样式字段放入共享 Schema；保留已知 SQL 表方角限制 |
| `cli.py`、`build_d2` | 自动模式无需新参数；可选配置路径用于覆盖，纯 API 接受已解析配置对象 | CLI 负责 I/O，纯生成函数不读文件；现有调用兼容，默认画面会因自动业务识别改变 |
| README、`dev_guide.md` | README 只加一个功能/选项，配置与限制放开发指南 | 区分历史原型和当前实现验证 |

SQL 解析、权限块策略、现有 SVG 原子发布机制不需要结构修改。无需新增 Python/Node/Java 依赖，也无需维护 D2 fork。变化集中在生成前的展示计划和 D2 发射层。

## 实施顺序、验证与回退

1. **MOVE**：移动纯发射函数，保持既有源码输出和测试不变。这一步可单独回退。
2. **ADAPT：业务区**：先写无配置的命名/关系推断测试，接入自动分区、标题、颜色和安全装箱；再实现覆盖配置及其失败测试。无配置调用和 source-only 检查必须保留。
3. **ADAPT：枢纽**：先加入 111/108 连线的长条回归用例，再实现自动两侧布局；补齐多枢纽、不同组尺寸和高密度图，验证收益适用边界。
4. **CLEAN**：删除重复发射/装箱路径，更新最小 README 和详细开发指南；不夹带 SQL 重构。

验收矩阵：

| 类型 | 必测条件 |
| --- | --- |
| 自动识别 | 多词前缀、通用技术前缀、同名跨 schema、无外键但命名清晰、命名与关系冲突、无语义表名、共享主表、加入不相关表后的标题/颜色稳定 |
| 配置 | 精确名称/通配、部分匹配、同名跨 schema、引号/中文、重复键、冲突规则、零匹配、非法字段/类型/颜色、空文件 |
| 拓扑 | 0/1/40/100 表、全孤立、多个连通分量同属一区、链、环、星形、密集图、多个枢纽、分区大小严重不均 |
| 外键 | 跨区复合键、同字段多条引用、自引用、重复声明；所有实际箭头对应正确字段对，已知自环限制显式保留 |
| 视觉 | 四个方向、clean/classic、长标题/字段、表高不同；无表重叠、区块标题不压表、每张表只出现一次 |
| 效果 | 对固定基准量化长宽比、面积、总线长、最长线；枢纽用例不能只靠缩小字号或隐藏字段通过 |
| 稳定性 | 打乱 Schema/关系输入顺序结果一致；相同配置与版本重复生成一致；显式组 ID/颜色稳定 |
| 失败路径 | 配置失败保留已有 D2/SVG；D2 缺失、版本不符、超时/无效 SVG 沿用现有错误和保留策略 |

每步使用原生项目命令验证：`python -m compileall -q erd_generator`、`python -m pytest -q`、`python -m ruff check .`、`python -m ruff format --check .`；真实渲染测试必须运行 pinned D2，不能静默跳过。

回退业务配置只需移除 `--layout-config` 参数并重新生成；回退自动分组/枢纽可使用 `--grouping none`。若需精确恢复旧版自动布局，回退对应布局变更。无需数据库迁移，CI/Docusaurus 的输入输出路径和发布顺序保持现状。

上述自动识别、覆盖配置、内层社区和枢纽策略已接入正常生成路径。当前验收记录与历史原型分开；自动布局仍不保证任意生产 schema 都达到人工逐表排版的效果。
